# EG13 — Design Spec

**Date:** 2026-10-20
**Repo:** github.com/SymbioticAudio/EG13 (GPL-3.0)
**Status:** approved in brainstorming, pending written-spec review

## 1. Purpose and scope

EG13 is an open-source software synthesizer that combines the DSP of Émilie Gillet's Eurorack modules (github.com/pichenettes/eurorack) into one playable bi-timbral instrument. It is a fixed-architecture synth with swappable engines in each slot, not a modular environment like VCV Rack.

- **Audience:** public open-source release.
- **Formats (v1):** CLAP (native) and AU v2, macOS 14+ (matching VizDAW and the symbiotic-design library), universal binary (arm64 + x86_64). VST3 and Standalone are built by the same wrapper and shipped as by-products.
- **Two plugins, one core:** EG13 is both an instrument and an audio processor (§2.3):

| | EG13 (instrument) | EG13 FX (effect) |
|---|---|---|
| Audio in | optional stereo sidechain | stereo main input |
| MIDI in | yes | yes, optional |
| Audio out | stereo main + optional stereo bus 2 | stereo main |
| AU type | `aumu` | `aumf` (MIDI-controlled effect) |
| CLAP features / VST3 category | instrument / Instrument | audio-effect / Fx |

  Both share engines, presets and UI.
- **Later:** Windows and Linux (new UI front-end on the same core API), AU v3 + iPadOS, original Blades model, Frames and Streams engines.

### 1.1 Naming and trademark

- "Mutable Instruments" is a registered trademark; the eurorack README asks derivative works not to use it or the module names. EG13 never uses the "Mutable Instruments" name in its product name, UI or marketing.
- The UI shows traditional synth-module names (table in §4), chosen so someone who has never used the original modules still knows what each engine does. Source code identifiers and docs may use the original module names to describe provenance. The About box and README carry factual credit: "DSP based on the open-source Eurorack firmware by Émilie Gillet."
- The plugin display name is a build setting separate from the codename, so it can change in one place.

## 2. Architecture

```
Audio in (sidechain or FX main input) ─► Input ─────────────┐ (to Audio Input, exciters,
                                                            │  Ring Mod modulator, Part FX)
MIDI in ─► PartRouter (mode, channel, key range, trigger)   │
Part ×2 ─┬─ VoiceAllocator (1–8 voices; poly / mono / legato; steal oldest-released, then oldest)
         ├─ Voice ×8: Source ─► Filter ─► Shaper ─► Amp ─► pan
         │            ▲ per-voice mod slots + fixed per-voice sources
         ├─ Σ voices ─► Part FX ─► level / pan / mono switch ─► bus
         └─ ModMatrix (12 routes)
Σ parts + Dry (Input, latency-compensated) ─► main stereo out (and optional bus 2)
```

### 2.1 Repository layout

```
/third_party/eurorack              submodule, unmodified
/third_party/eurorack-patches      minimal documented patches, only if unavoidable
/third_party/AudibleInstruments    submodule (Ripples/Shelves DSP, reference)
/third_party/sst-filters, clap, clap-wrapper, r8brain-free-src, Catch2   submodules
/core        C++17 synth core; no OS, plugin or UI dependencies
   engine/     engine interfaces + one adapter per module
   resample/   NativeRateWrapper
   voice/ part/ mod/ params/ state/
/core-api    narrow C API over the core (used by the plugin and every UI)
/plugin      CLAP plugin in C++; clap-wrapper targets for AU v2, VST3, Standalone
/ui-swift    Swift package EG13UI (SwiftUI), embedded through NSHostingView
/tests       core unit tests, fidelity tests, golden renders, benchmarks
/docs
```

Build: CMake for C++ and plugin targets; SwiftPM for `/ui-swift`, linked into the plugin bundle by the CMake build.

### 2.2 Key rules

- `/core` builds and tests on macOS and Linux with no platform code.
- The audio thread never allocates, locks or waits on the UI.
- Every engine type is preallocated for every slot of every voice at plugin load, so switching engines is a pointer swap. If measured memory is unacceptable, the fallback is allocation on a background thread with the switch applied when ready.
- All Swift and Objective-C symbols carry an `EG13` prefix to avoid clashes with other plugins in the same host process.

### 2.3 Audio input

Either plugin's audio input (instrument sidechain, FX main input) becomes one stereo core signal, **Input**. When no input is connected, Input is silence. Input is used by:

- **Audio Input** source engine: Input enters each voice's chain; MIDI notes gate it through Filter, Shaper and Amp.
- **Exciter input** on Resonator and Modal Synth sources: internal exciter, Input, or both.
- **Ring Mod / Vocoder** modulator selector (§4).
- **Part FX input** selector per part: Part mix / Input / Part mix + Input.

**Dry level** (master parameter) mixes Input into the main output, delayed by the plugin's reported latency so it stays aligned with the wet signal.

**Other part as input (decided 2026-10-20):** each place that takes Input has a per-part **Input source** selector: *External* (the plugin input), *Other part* (the other part's post-FX output) or *Both* (summed). Example patches: Part A's percussion exciting Part B's Resonator tuned by chords; Part A's speech model vocoding Part B's pad through Ring Mod / Vocoder; Part A's melody captured by Part B's Granular; an Always-on drone in Part A gated per key by Part B's Audio Input voices.
- **Direction and delay:** Part A is processed before Part B, so A → B has no extra delay. B → A uses B's output from the previous block (one block of delay). If both parts take each other as input (a loop), each feedback path passes through a soft limiter so it cannot run away.
- **Output routing:** the part Output setting gains a third value, *Other part only*: the part feeds the other part's input and is not heard directly. Existing values keep their meaning (0 = main, 1 = Bus 2, 2 = other part only).

Both plugins are built from one CLAP bundle exposing two plugin IDs through the CLAP factory, with clap-wrapper producing the `aumu` and `aumf` AU components. M0 verifies clap-wrapper supports this; if it does not, the fallback is two CLAP bundles built from the same sources.

## 3. Engines

### 3.1 Interfaces

```cpp
class VoiceEngine {                     // Source, Filter, Shaper slots
  virtual void prepare(double hostRate, int maxBlock) = 0;   // only place that allocates
  virtual void reset() = 0;
  virtual void noteOn(float note, float velocity) = 0;       // note: float MIDI note
  virtual void noteOff() = 0;
  virtual void process(const float* const* in, float* const* out,
                       const ParamValues& p, int n) = 0;     // p: post-modulation, normalized 0..1
  virtual const EngineInfo& info() const = 0;                // display name, param descriptors
};
class PartFxEngine;   // stereo in → stereo out, same param model, no notes
class ModEngine;      // K control outputs, gate/trigger inputs, same param model
```

`EngineInfo` lists each parameter's display name, range, curve, unit and default, plus non-continuous settings (e.g. Plaits model, Clouds mode).

### 3.2 Native rate

Each MI module runs at its own native sample rate and block size inside a `NativeRateWrapper`: input/output FIFOs plus r8brain conversion to and from the host rate, bypassed when the rates match. Parameters are applied at native block boundaries. The plugin reports one fixed latency equal to the worst-case wrapper latency, and every engine is delay-compensated to that latency so switching engines never shifts timing.

### 3.3 Adapters

Each adapter handles its module's control conventions (trigger/level/gate/strum, pitch units, int16 audio for Braids, mono mode for Rings as a source). Knob-to-parameter mappings follow VCV AudibleInstruments where it has a port. A module that keeps static state preventing multiple instances gets a patch in `eurorack-patches`, each documented with the reason.

Ring Mod / Vocoder modulator sources:
- **Source AUX:** the Source's secondary output (Macro Oscillator AUX, Resonator even partials); other sources fall back to their main output.
- **Input:** §2.3.
- **Other part:** the other part's post-FX mix from the previous block (one block of delay; avoids a processing loop between parts).

Excluded from v1: Blades (no code), Tides v1 (superseded), utilities (Kinks, Veils, Links, Blinds, Shades), hardware-only and MIDI modules (Ears, Volts, Yarns). Backlog: Frames (morph mod source), Streams (Shaper/Amp), Edges (Source), Grids/Branches (note generation).

## 5. Voice and part

### 5.1 Signal format

The voice chain carries 2 channels. Mono engines write the same signal to both. A Filter or Shaper runs a second instance only while its input is stereo. Each voice has a pan.

### 5.2 Amp

The Amp is a destination in the matrix. If any route targets Amp, the Amp level is the sum of those routes (clamped 0..1) × Amp gain. If no route targets Amp, the Amp follows the gate with 5 ms attack and release ramps. A voice is freed when its note is off and its output stays below −90 dBFS for 50 ms.

### 5.3 Parts

Two parts, A and B. Settings per part: MIDI channel (omni / 1–16), key range (low/high), transpose, voice mode (poly / mono / legato), voices (1–8), glide, pitch-bend range, level, pan, Mono switch (sums to centre after Part FX), output (main, Bus 2 or other part only), Part FX input (§2.3), Input source (external / other part / both, §2.3), trigger, base note.

**Trigger:** *MIDI* (normal) or *Always on*. Always on holds one voice open permanently at the part's **Base note** with gate high, so the part processes Input with no MIDI. Incoming notes on an Always-on part change its pitch (mono, legato) but do not retrigger.

Global mode switch sets part settings:
- **Single** — only A plays.
- **Layer** — A and B on the same keys.
- **Split** — A below the split note, B from the split note up.
- **Multi** — A and B on their own MIDI channels.

## 6. Modulation

- **Mod slots:** 4 per part. Each holds any ModEngine (duplicates allowed) or is empty. Scope per slot: **per-voice** (one instance per voice, retriggered on note-on) or **per-part** (one shared instance).
- **Fixed sources:** velocity, release velocity, note (keytrack), gate, per-voice random (new value each note), poly aftertouch / MPE pressure, MPE slide (CC74), per-note pitch bend, mod wheel, pitch bend, channel pressure, 4 MIDI-learnable CCs, host transport phase.
- **Matrix:** 12 routes per part. Route = source, destination, bipolar amount, optional *via* source (multiplies the amount). Destinations: any slot parameter, voice pitch, Amp, pan, part level, and parameters of mod slots. Routes add in normalized space and clamp to 0..1.
- **Rate:** control rate every 16 host samples, smoothed per engine; pitch interpolated per sample. No audio-rate cross-slot FM in v1.
- **Init patch:**

| Slot | Engine | Route |
|---|---|---|
| Mod 1 | Envelope (ADSR), per-voice | → Amp, via velocity, amount 100% |
| Mod 2 | Envelope (ADSR), per-voice | → Filter P1 (cutoff), +30% |
| Mod 3 | LFO (LFO mode), per-voice | → pitch, via mod wheel, ±0.5 semitone |
| Mod 4 | empty | |
| — | pitch bend | → pitch, ±2 semitones |

The EG13 FX init patch is: mode Single; Part A trigger Always on; Source Audio Input → Filter Analog Filter → Part FX Granular; Mod 1 LFO (per-part) → Filter P1, +20%; Dry level 0.

## 7. Parameters and state

### 7.1 Host parameters

Per part, a fixed set of generic slot parameters:

- Source: engine, P1–P8
- Filter: type, P1–P4
- Shaper: type, P1–P6
- Part FX: type, P1–P8
- Mod slots 1–4: engine, scope, P1–P6
- Matrix: route amounts 1–12
- Part settings that are continuous: level, pan, glide, transpose, base note
- Part settings that are stepped (exposed as stepped host parameters so they are editable in hosts before the custom UI exists; decided 2026-10-20): MIDI channel, key range low/high, voice mode, voice count, trigger, pitch-bend range, Mono switch, output bus
- Master: output level, Dry level, mode (Single / Layer / Split / Multi), split note

Each engine maps its own controls onto P1…Pn and supplies display names. CLAP updates names live through param rescan; AU and VST3 hosts may show generic names ("A Src P2"). Parameter IDs are stable and never renumbered. Route sources and destinations, engine non-continuous settings and Envelope multi-segment shapes are patch data, not host parameters. Exception (decided 2026-10-20): the Macro Oscillator's Model is its P1, automatable like the hardware's MODEL CV input.

### 7.2 State

- Host parameters and patch data are serialized together as JSON with a `schemaVersion`.
- Migration functions upgrade older versions; any 1.x project opens in later 1.x.
- Per-engine settings are kept per slot, so switching Macro Oscillator → Digital Oscillator → Macro Oscillator restores the Macro Oscillator settings.

### 7.3 Presets

- **Patch** (`.eg13patch`): one part; loads into A or B.
- **Performance** (`.eg13perf`): both parts + mode.
- Factory presets ship inside the bundle; user presets live in `~/Library/Application Support/SymbioticAudio/EG13/Presets`.
- v1 browser: category, previous/next, save, init. Tags and search later.

## 8. UI

- SwiftUI, Swift package `EG13UI`, embedded in the CLAP gui extension's NSView via NSHostingView (also used by the AU and VST3 wrappers).
- Design language: **symbiotic-design** package (shared with VizDAW) for tokens, themes and icons; EG13 never defines its own tokens or icons, it requests them in symbiotic-design's HANDOFF.md. Four themes, matching VizDAW; theme follows system or is fixed in settings. Controls come from AudioKit Controls/Keyboard styled with those tokens. Branded glyphs are used when present; otherwise MIT standard icons, then Lucide.
- Window ~1200 × 760 at 100%, scalable 75–200%.
- Layout (top to bottom): header (preset name with prev/next/save, mode segmented control, A/B part tabs, settings, about); slot row (Source, Filter, Shaper, Part FX cards with engine selector and named knobs with modulation rings); mod row (4 mod cards with engine, scope, knobs, live shape display); matrix list beside part settings and meter; collapsible keyboard showing split point and part colours.
- Modulation assignment in v1: knob context menu "Modulate from…" or adding a matrix row. Drag-to-assign later.
- Plumbing: parameter edits go through CLAP param events with begin/end gestures. Other edits go through `/core-api` commands, applied on the audio thread via a lock-free queue. The UI reads a snapshot (values, modulated values, meters, mod displays) at display rate.
- Accessibility: VoiceOver labels and values on every control; keyboard focus navigation.

## 9. Error handling

- Engine or preset load failures never stop audio: the slot falls back to Off (or Init patch for a preset) and the UI shows a message.
- Unknown engine IDs or newer `schemaVersion` in a preset: load what is understood, keep unknown data untouched on resave, and warn.
- Audio thread guards: NaN/Inf in any engine output resets that engine and mutes the voice for one block; denormals flushed (FTZ/DAZ) in `process`.
- Host sample-rate or block-size change: `prepare` re-runs off the audio thread; output is silent until done.

## 10. Testing and CI

- **Unit tests** (Catch2, `/core`): voice allocation and stealing, part routing, matrix maths, parameter mapping, state round-trip, schema migration, resampler.
- **Fidelity:** at host rate = native rate, each adapter's output equals the bare module's output bit for bit for the same inputs. At other rates: pitch accuracy within 1 cent; aliasing limits per resampler spec.
- **Golden renders:** fixed MIDI scripts per engine and per factory preset; exact comparison for deterministic engines, spectral tolerance otherwise.
- **Real-time safety:** test build traps allocation and locks on the audio thread; stress test switches engines and loads presets while notes play.
- **Plugin validation:** clap-validator, auval (both `aumu` and `aumf`), pluginval (VST3) in CI; manual checks in Logic, Reaper, Bitwig and VizDAW, including sidechain routing to the instrument and the FX plugin on an audio track.
- **Input path:** Dry output equals Input delayed by the reported latency (sample-exact); Always-on part produces output from Input with no MIDI.
- **CPU benchmark:** per-engine per-voice cost tracked in CI. Budget: a 2 × 8-voice patch of the heaviest engines runs below 50% of one M1 performance core at 48 kHz, 128-sample blocks.
- **UI:** Swift Testing for view models; manual checklist (themes, scaling, VoiceOver).
- **CI:** GitHub Actions. Linux + macOS build and test `/core`; macOS builds the plugin, runs validators, uploads unsigned artefacts. Signing and notarisation added in M7.
