# EG13 M5 (Part FX) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give each part a Part FX slot after Σ voices (Off, **Granular** from Clouds, **Granular Delay** from Beads, **Resonator** from Rings, **Reverb** from Elements' reverb) with the Part FX input selector (Part mix / Input / Part mix + Input), host parameters (type, P1–P16, input selector), matrix routing into Part FX P's, state schema 6, EG13 FX's init Granular, and latency, CPU and memory reports.

**Architecture:** Part FX engines are `VoiceEngine`s like every other slot's, each in its own `NativeRateWrapper` at the module's native rate, held by one `ProcessorSlot` per part (preallocated, padded to one slot latency, crossfaded on a type change). A new `PartFx` class in `core/part/` owns that slot, picks its input by the selector, delays the Input and the bypassing voices so everything stays aligned, and replays per-tick controls (P's after modulation, the part's note, note triggers) delayed by the voices' latency so they act on the sound they belong to. `Part` runs it between the voice mix and level / pan / Mono. Routes into Part FX P's are part-level destinations, evaluated once per 16-sample tick like Part Level. The Synth stashes Part FX settings per engine exactly like the other slots.

**Tech Stack:** C++17, CMake + Ninja, Catch2 v3, r8brain-free-src 7.6, upstream pichenettes/eurorack at f4cfa76 (Clouds, Beads, Rings, Elements + stmlib, unmodified), nlohmann/json, CLAP 1.2.10, clap-wrapper v0.16.0.

**Spec:** `docs/superpowers/specs/2026-10-20-eg13-design.md` (M5 row of §11; §2 diagram; §2.3 Part FX input selector and Input source; §3.1–3.3; §4 Part FX rows; §5.3 part settings; §6 Rate and the EG13 FX init patch; §7.1 "Part FX: type, P1–P8"; §7.2; §9; §10).

**Branch:** `m5-part-fx`, based on `main` at `974ad47` (M4 merged). Do not switch branches.

- Stepped Part FX P's are append-only option lists read in `kPartFxSelectorSteps` (16) fixed steps; steps past the last option read as the last option. Switches (Freeze) are on at ≥ 0.5.
- Matrix destination codes `kDestPartFxP + p` (64..79, reserved by M4 provisional ruling 16) become live; no code is renumbered.
- Native rates and blocks: Granular 32000 Hz / 32 (`clouds/dsp/frame.h:37`, VCV `Clouds.cpp:139-197`); Granular Delay at its Quality's codec rate, 4000 blocks per second (`beads/beads.cc:50,277`; `beads/dsp/processor.h:47-55` with `ENABLE_HARDWARE_24K`): Digital 48000 / 12, Vintage digital 32000 / 8, Clean tape 48000 / 12, Dirty tape 24000 / 6; Resonator 48000 / 24 (`rings/dsp/dsp.h:39-41`); Reverb 32000 / 16 (`elements/dsp/dsp.h:38-39`).
- Fidelity (spec §10): at host rate = native rate each adapter matches the bare module bit for bit. References drive the upstream classes directly from the firmware's (or VCV's) process loop, never adapter code. Clouds and Beads draw from `stmlib::Random` (thread-local): a reference and its adapter run each start from `stmlib::Random::Seed(1)`.

The first block after `reset()` snaps. Smoothing bullets go in `docs/manual/smoothing.md` before its "After a reset" paragraph.

## Planning measurements (2026-10-23, this machine, -O3)

- **Wrapper input-path latency** for a 2-in / 2-out engine (r8brain 7.6, `kTransitionBandPercent` 30): 32 kHz engines 472 / 539 / 1077 host samples at 44.1 / 48 / 96 kHz (10.7 / 11.2 / 11.2 ms); Beads Dirty tape (24 kHz) 445 / 444 / 932; Beads Vintage digital (32 kHz) 406 / 467 / 933; 48 kHz engines 232 / 0 / 468. The Part FX slot latency is therefore Granular's, ≈ 539 samples at 48 kHz.
- **CPU per instance, bare module at native rate:** Clouds 0.23–1.06 % of a core (Spectral, 16-bit, worst), Beads 0.30–1.30 % (Digital, Size 100 %, worst). `sizeof(clouds::GranularProcessor)` 9096 B, `sizeof(beads::Processor)` 25824 B.

## Provisional rulings (flag for owner)

Each line: what was chosen — why — what it costs to change.

1. **Part FX has P1–P16, not P1–P8** (Task 1 amends spec §7.1): Granular needs 13 controls (VCV `Clouds.cpp:6-21`: nine knobs, In Gain, Freeze, Mode, Quality), Granular Delay 15 (`beads.cc:183-236`: eight knobs, four randomisation attenuverters, Freeze, Quality, Seed) — the M3 Shaper precedent; the IDs and the M4 code space (64..79) already have room — fewer P's would mean making Mode / Quality patch data.
2. **Part FX engines are `VoiceEngine`s** (spec §3.1 names a `PartFxEngine` class): they reuse `NativeRateWrapper`, `ProcessorSlot`, padding and crossfades; `noteOn` carries the part's note triggers and `setNote` its pitch — the spec's "no notes" cannot hold for a Resonator whose pitch follows notes — a separate interface would need its own wrapper.
3. **P layout and one host default per P position** (CLAP has one default per parameter, M3 ruling I1): P1–P4 0.5, P5 0.75, P6 0.5, P7–P12 0, P13–P16 0.5; every engine's own defaults equal these, so a host reset never changes a Part FX from its defaults. P1 is the Mix of every engine, so "Part FX P1" always means dry/wet. — the shared value per position — moving a control later re-meaning saved projects (fine before release).
   - Granular: P1 Blend, P2 Position, P3 Size, P4 Pitch, P5 Density, P6 Texture, P7 Feedback, P8 Reverb, P9 Freeze, P10 Mode, P11 Quality, P12 Spread, P13 In Gain.
   - Granular Delay: P1 Dry/Wet, P2 Time, P3 Size, P4 Pitch, P5 Density, P6 Shape, P7 Feedback, P8 Reverb, P9 Freeze, P10 Quality, P11 Seed, P12 unused, P13 Time Random, P14 Size Random, P15 Shape Random, P16 Pitch Random.
   - Resonator: P1 Mix, P2 Structure, P3 Brightness, P4 Damping, P5 Spread, P6 Position, P10 Model, P11 Polyphony, P13 Tune; others unused.
   - Reverb: P1 Amount, P2 Time, P3 Diffusion, P4 Brightness, P9 Freeze; others unused.
4. **Density defaults to 75 %** on Granular and Granular Delay, not VCV's 50 %: both modules make no grains between about 47 % and 53 % (`clouds/dsp/granular_processor.cc:97-102`, `beads/dsp/trigger_generator.cc:265-280`), so the EG13 FX init patch would only blend dry — one default.
5. **Wet/dry:** Granular and Granular Delay use their own dry/wet (the module's dry path, including Beads' bit-reduced dry and Clouds' 16 kHz band limit at 32 kHz); Resonator gets an EG13 Mix (linear dry/wet inside the adapter at its native rate); Reverb's Amount is Elements' own crossfade — keeps each module's character and bit-exact fidelity — a host-rate dry path in `PartFx` is the alternative.
6. **Granular In Gain:** P13 maps to gain 2 × P (50 % = unity: EG13 ±1.0 reaches Clouds' int16 full scale, as VCV's ±5 V does at gain 1.0); the input is clamped to int16 as VCV does (`Clouds.cpp:120-121,151-152`) — EG13's default level passes unchanged — a mapping constant.
7. **Granular Pitch:** P4 is ±24 semitones (VCV ±2 V × 12, `Clouds.cpp:72,167`); it does not track notes (a route from Note can) — the hardware's V/OCT is a jack — a tracking switch could be appended.
8. **Triggers from notes:** every note-on the part plays (a voice trigger, not a legato glide; on an Always-on part, every key press) sends one trigger to the Part FX: Granular's TRIG (sets `trigger` and `gate` for one block, `Clouds.cpp:133-135,162-163`), Granular Delay's SEED gate when Seed = Notes (a 1 ms gate), the Resonator's strum — notes are the only gate source a part has — a route-driven trigger is a later addition.
9. **Granular Delay Seed:** *Free* (SEED unpatched: Density alone makes grains) / *Notes* (note-ons patched into SEED: below 48 % Density divides the note clock, above 52 % it is the probability, in between every note is a grain, `trigger_generator.cc:132-137,255-290`); the seed button and the firmware's 2.5 ms seed delay (`beads.cc:141-148`) are not used — default Free keeps the module's normal behaviour — a list append.
10. **Granular Delay runs at its Quality's codec rate** (24 / 32 / 48 kHz): one `beads::Processor` (one set of buffers, as the hardware shares them across qualities) is driven through three inner wrappers, one per rate, padded to the slowest; a Quality change fades out over 10 ms, calls `Configure`, restarts the new rate's conversion and fades in over 10 ms (the hardware mutes 250 ms, `beads.cc:292`) — running all qualities at 48 kHz would halve Dirty tape's times — removing the nested wrappers is local to `BeadsEngine`.
11. **Granular Delay input stage:** no automatic gain control (EG13's gain staging sets levels); input at unity, clamped to ±1 as the manual-gain path does; Dirty tape adds the manual path's soft clipping at amount 1 (`beads/gain_control.cc:149-166`); stereo always (`Configure(media, false)`); the wavetable synth mode, assignable CV and output gate are left out — the parts of the firmware a part's insert needs — each is an append.
12. **Resonator as Part FX:** one Rings instance per part, the part mix as its exciter (internal exciter off), Polyphony 1 / 2 / 4 (default 1, as the module), strum on every part note-on with that note (the hardware with V/OCT patched strums only on a changed note, `rings/dsp/strummer.h:65-70`), velocity ignored (1.0) — playable in both trigger modes — a branch in `RingsFxEngine`.
13. **Resonator pitch:** the note of the part's most recently started voice + transpose + the part's pitch bend + Tune (±12 st); before any note, and on an Always-on part with no key held, the Base note (an Always-on part follows the held key, as its voice does) — spec §4's "last note (or Base note when Always on)", made consistent with spec §5.3 — one function in `Part`.
14. **Reverb mappings:** Amount → `set_amount(P)`; Time → `set_time(0.35 + 0.63 P)` (the range Clouds gives the same topology, `granular_processor.cc:270`); Diffusion → `0.55 + 0.15 P` (`elements/dsp/part.cc:99`); Brightness → `set_lp(0.6 + 0.37 P)` (`granular_processor.cc:272`); input gain 0.2; Freeze → time 1.0, input gain 0, lp 1.0 (`elements/dsp/part.cc:240-244`) — Elements' Space knob packs these into one control — constants.
15. **Part FX input selector:** *Part mix* (Σ voices into the FX), *Input* (the part's Input, as its Input source routes it, into the FX; the voices bypass the FX, delayed by the slot latency, and are added after it), *Part mix + Input*; with Part FX Off the selector is ignored and the part mix passes — "Input" must not silence the part's own voices, and Off must not leak the Input — a branch in `PartFx`.
16. **Alignment:** Input entering the Part FX is delayed by the voices' latency, so FX(Input) leaves the part at the reported latency, exactly with Dry, in both plugins; Part FX P's (host and routed), the part's note and the triggers act after the voices' latency, on the 16-sample grid — the M4 rule that each control lines up with the audio it acts on — an event ring would give sample-exact triggers.
17. **Latency:** every Part FX engine, Off included, is padded to the slowest (Granular, ≈ 539 samples at 48 kHz), and the plugin reports voice latency + Part FX slot latency: about 22 ms (instrument) and 28 ms (EG13 FX) at 48 kHz, up from 10.9 / 16.5 ms — spec §3.2's constant-latency rule — the owner may prefer reporting it only while a part uses Part FX (a latency change needs a host restart) or a wider r8brain transition band for Part FX.
18. **Type change:** the old engine keeps running for the slot latency, then a 10 ms crossfade (`kSlotFadeSeconds`) to the new engine, which starts empty; the old engine's tail is cut — the Filter/Shaper rule, and spill-over would run two engines — a longer fade is a constant.
19. **Part FX always runs while not Off**, also with no voices sounding (frozen buffers, tails and Always-on input keep playing) — skipping on silence would cut frozen loops — a silence gate could be added for Reverb only.
20. **Part-level sources for Part FX routes:** routes into Part FX P's read per-voice sources from the most recently started voice, as Part Level (M4 ruling 6).
21. **NaN guard:** a non-finite Part FX output restarts the playing engine and outputs silence for that slice (spec §9).
22. **Defaults per plugin:** instrument Part FX Off on both parts; EG13 FX Part A Granular (spec §6), Part B Off; Part FX input Part mix everywhere.
23. **CPU budget for Part FX:** the 50 % voice-chain budget and the 10 % modulation budget are unchanged; Part FX gets its own: at most 5 % of one M1 core for both parts each running its costliest Part FX setting (including rate conversion), 48 kHz, 128-sample blocks. Planning measured ≤ 1.3 % per bare instance. If it fails, report the figures and stop — separate budgets as in M4 — the owner may merge budgets.
24. **Memory** is measured per part (Task 9) and documented; planning estimate ≈ 1.2 MB of module buffers per part (Beads 832 KiB, Clouds 180 KiB, two 64 KiB reverbs) plus converters.

## Review Focus

1. **Changing Part FX type, Quality or Mode while sounding, or automating them:** no click beyond the 10 ms fade, never NaN, output stays aligned, P values follow the engine. Pinned in Task 4 ("Quality changes fade and keep the latency") and Task 9 ("Switching Part FX type while sounding crossfades and keeps alignment").
2. **Input selector with nothing on the Input** (no sidechain; Input source Other part in Single mode): the FX gets silence, the voices are still heard, Off never leaks Input. Pinned in Task 9 ("Input mode with no Input keeps the voices and adds silence", "Off ignores the input selector").
3. **Host rates and slicing** (44.1 / 96 kHz; 1-, 7- and 129-sample blocks), especially Granular Delay through its nested 24 kHz wrapper: finite, aligned, same output whatever the slicing. Pinned in Task 4 ("Every Quality through the wrapper at 44.1, 48 and 96 kHz with odd blocks") and Task 9 ("Part FX does not depend on host block slicing").
4. **Runaway settings** (Feedback and Reverb at 100 %, Freeze for minutes, Density extremes, full-scale input): bounded output, no NaN. Pinned in Task 3 and Task 5 ("Maximum feedback and reverb stay bounded for 60 s") and Task 6.
5. **Parts feeding each other through Part FX** (A's FX input = Input with Input source Other part, and B likewise): bounded by the existing soft limiter, no runaway. Pinned in Task 11 ("Two parts feeding each other through Granular stay bounded").
