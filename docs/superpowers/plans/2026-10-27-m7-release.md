# M7: Release (implementation plan)

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** EG13 v1.0.0. It opens on a delightful first patch, has three preset banks (Bank 1, Bank 2 "catnap", and FX) plus a User bank, all browsable from the header. It installs from a GitHub Release, can be signed and notarised once credentials exist, has docs a stranger can follow, and its reusable design work is offered to symbiotic-design.

**Architecture:**
- **Core:** a new `core/preset` module turns the current state into a preset file, and applies a preset file to the current state. It works by editing the state JSON that `StateStore` already reads and writes, so presets and host projects share one format and one load path.
- **Preset kinds:** a Performance replaces the sound of both parts. A Patch replaces one part's sound and can go into A or B. Neither touches the user's setup fields.
- **Factory presets:** written as readable *preset sources* (engine and parameter names, not IDs). A build tool compiles them into a table embedded in the plugin binary, because bundles have no resource mechanism. The same tool decompiles a User preset back to source, and renders presets to WAV for listening and for golden tests.
- **C API:** gains preset functions. The Swift side owns the browser model and the User folder; the core owns the preset format.

**Tech stack:** C++17, nlohmann/json, CLAP 1.x via clap-wrapper v0.17.0, Swift 6 and SwiftUI on macOS 14+, symbiotic-design 0.1.0, Catch2, Swift Testing, GitHub Actions, `codesign`/`notarytool`/`pkgbuild`/`productbuild`.

## Planner decisions (for owner review with this plan)

1. **Setup fields** that a preset never changes (design §9):
   - per part: `PartParam::MidiChannel`, `Output`, `MpeMode`, `MpeBendRange`, `CcA`–`CcD`;
   - master: `MasterParam::Level`, `VoiceGain`, `LatencyMode`.
2. **What a Patch covers:** everything in one part except the setup fields, **and also except `KeyLow`/`KeyHigh`.** The key range belongs to how the two parts are laid out, so it stays with the Performance. A Patch never changes master settings.
3. **File format:**

   ```json
   { "eg13Preset": 1, "kind": "performance" | "patch", "plugin": "instrument" | "effect",
     "name": "...", "bank": "...", "note": "...", "credit": "...", "licence": "...", "state": { ...StateStore JSON... } }
   ```

   - Extensions are `.eg13perf` and `.eg13patch`. A Patch's `state` holds its part as part 0.
   - A file whose `plugin` doesn't match the running plugin is refused, with a message.
4. **Preset sources:**
   - **Location:** `presets/bank1/`, `presets/bank2-catnap/`, `presets/fx/`, one `<slug>.json` each.
   - **Names:** engines, parameters, route sources and destinations are named as in the UI tables.
   - **Values:** normalised 0–1, or an option name for stepped parameters.
   - **List order:** a sorted `"order"` integer.
   - **Banks as shown:** "Bank 1", "Bank 2", "FX", "User".
5. **Golden tests:** render each factory preset for 12 s with a fixed note script. Store a level envelope (RMS per 250 ms, in dB) in `tests/data/preset_golden.json`. Pass when every frame louder than −60 dB is within ±1.5 dB of the stored value.
   - This replaces the parent spec's "exact comparison" for presets, because several engines are random and the Linux and macOS compilers differ.
6. **Browser state in the project:** a new top-level state key `"browser"` holds an opaque JSON string owned by the UI: the loaded names, the kinds and the edited flag. `StateStore` saves and restores it. The schema version stays at 6.
7. **First load:** a new *instrument* instance applies the factory preset whose source has `"firstLoad": true`. The `Synth` constructor and every existing test keep Init. EG13 FX opens on its init patch.
8. **Order of work:** the owner can't test for a while. So the engineering, clean-up, release and docs tasks run first. Preset drafting runs next. The by-ear gates collect into one listening queue that the owner works through when they have time. v1.0 is tagged only when every gate is approved.

## Review Focus

1. **Loading a preset while notes play** (arrows held down, or a Patch into B during a chord): no crash, no allocation on the audio thread, and no stuck notes. Pinned in Task 3.
2. **A broken or foreign preset file in the User folder** (truncated JSON, a newer `eg13Preset`, an FX preset in the instrument, a non-preset file): the file is skipped or refused with a message, the rest of the list works, and audio continues. Pinned in Tasks 1 and 4.
3. **Save As with a name that exists, an empty name, or a name with `/` `:` or emoji:** a clash asks to replace; the file name is sanitised but the shown name kept; an empty name is refused. Pinned in Task 4.
4. **Reopening a project:** the header shows the same preset name and edited mark as when it was saved, and a project saved before M7 shows "Init". Pinned in Task 3.
5. **A factory preset source that names an engine or parameter that no longer exists:** the build fails with the preset and the name, so it can't ship silently broken. Pinned in Task 2.
